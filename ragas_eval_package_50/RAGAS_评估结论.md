# RAGAS 评估结论

## 评估范围

- 评估对象：当前纯 RAG 基线方案
- 评估数据：`ragas_eval_50.jsonl`
- 样本数量：50 条
- 评估方式：
  - 先由项目内部 `RAGChain` 生成 `question / answer / contexts / ground_truth`
  - 再使用 RAGAS 做离线评估
- Judge 模型：DeepSeek API `deepseek-v4-flash`
- 评估嵌入模型：`E:\AI_model\models\bge-m3`

## 评估结果

```json
{
  "faithfulness": 0.7654692133263562,
  "answer_relevancy": 0.80583426344469,
  "context_precision": 0.708333333297619,
  "context_recall": 0.7674418604651163
}
```

## 指标解读

- `faithfulness = 0.765`
  表示回答大多数情况下能够依据检索到的上下文作答，整体幻觉风险较低，但仍存在少量自由发挥或过度概括。

- `answer_relevancy = 0.806`
  表示回答整体能够对准用户问题，答偏的情况不多，问题响应性较好。

- `context_precision = 0.708`
  表示检索结果中大部分上下文是有效的，但仍夹杂一定噪声，检索精度还有优化空间。

- `context_recall = 0.767`
  表示系统大多数情况下能够召回关键依据，但仍有部分问题存在信息召回不全的情况。

## 总体结论

本次 50 条样本评估结果表明，当前纯 RAG 方案已达到“整体可用”的水平，表现为：

- 大多数问题能够得到相对相关且有依据的回答
- 检索质量整体稳定，关键证据大多数情况下能够召回
- 回答的相关性较好，说明问答主链路已经基本跑通

同时，这套方案距离“高可靠、高精度”的目标仍有一定差距，主要体现在：

- 检索结果中仍有部分噪声，影响上下文纯度
- 回答虽然整体可信，但还存在一定自由发挥空间
- 某些问题可能没有完整召回关键条款，导致答案不够充分

因此，可以将当前版本判断为：

`一个中上水平、具备实际使用基础的纯 RAG 基线版本。`

## 业务化解读

如果从业务角度理解，这组结果说明：

- 系统大多数时候“答得上”
- 回答大多数时候“有依据，不乱编”
- 检索结果“基本够用，但还不够干净”
- 关键依据“多数能找到，但还不是每次都找全”

换句话说，当前系统已经具备上线前进一步优化和灰度验证的基础，但仍建议在正式高风险场景使用前继续提升检索精度和答案稳定性。

## 优先优化建议

建议后续优先按以下顺序继续优化：

1. 提升检索精度
   重点关注 `context_precision`，减少无关 chunk 混入。

2. 降低回答自由发挥
   重点关注 `faithfulness`，让回答更严格约束在检索证据之内。

3. 提升关键证据召回完整性
   重点关注 `context_recall`，减少“资料里有但没捞全”的情况。

4. 做参数对比实验
   建议重点对比以下配置：
   - `RETRIEVAL_TOP_K=3` 与 `RETRIEVAL_TOP_K=5`
   - `hierarchical` 与 `recursive` 切分策略
   - `ENABLE_QUERY_REWRITE` 开 / 关

## 结论摘要

本次 RAGAS 评估显示，系统在 50 条样本上的整体表现较稳定，已具备可用性基础；下一步优化重点应放在“检索更准”和“回答更稳”上，而不是先推倒整体架构重做。
