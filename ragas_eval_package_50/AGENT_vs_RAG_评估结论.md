# Agent vs 纯 RAG 评估结论

## 1. 评估对象

- 纯 RAG 基线：`ragas_summary_50_deepseek.json`
- Agent 版本：`ragas_agent_summary_50_deepseek.json`
- 评估样本数：50 条
- Judge 模型：`deepseek-v4-flash`
- Embedding 模型：`E:\AI_model\models\bge-m3`

## 2. 核心结果对比

| 指标 | 纯 RAG | Agent | 差值 |
| --- | ---: | ---: | ---: |
| faithfulness | 0.7655 | 0.8275 | +0.0620 |
| answer_relevancy | 0.8058 | 0.8113 | +0.0055 |
| context_precision | 0.7083 | 0.7760 | +0.0677 |
| context_recall | 0.7674 | 0.7857 | +0.0183 |
| route_accuracy | - | 1.0000 | +1.0000 |

## 3. 怎么解读 Agent 评估结果

### 3.1 回答是否更“站得住”

`faithfulness` 从 `0.7655` 提升到 `0.8275`，说明 Agent 版回答更能依据检索到的证据作答，乱补充、乱发挥的情况更少。

换成业务语言就是：

- 回答更像“按资料说话”
- 幻觉风险更低
- 在规范问答、制度条款问答里更可靠

### 3.2 回答是否更“对题”

`answer_relevancy` 从 `0.8058` 提升到 `0.8113`，增幅不大，但说明 Agent 至少没有把答案带偏，整体问答对题性略有提升。

换成业务语言就是：

- 用户问什么，系统基本能答到点上
- Agent 的加入没有破坏主问答链路
- 说明路由增强是“稳中有升”，不是“功能变多但回答变散”

### 3.3 检索结果是否更“干净”

`context_precision` 从 `0.7083` 提升到 `0.7760`，这是很明显的一次提升，说明 Agent 最终用于回答的上下文更相关、噪声更少。

换成业务语言就是：

- 喂给模型的资料更准了
- 无关片段混进来的情况减少了
- 这通常会直接改善最终答案质量和稳定性

### 3.4 关键证据是否更“找得全”

`context_recall` 从 `0.7674` 提升到 `0.7857`，说明 Agent 版在多数情况下能更完整地拿到回答所需证据。

换成业务语言就是：

- 资料库里明明有的内容，更容易被真正拿出来用
- 漏掉关键条款、关键条件的概率更低
- 对多条件、多步骤类问题更有帮助

### 3.5 路由是否正确

本次 Agent 评估中：

- `route_eval_count = 50`
- `route_match_count = 50`
- `route_accuracy = 1.0`

这表示在你当前这 50 条样本上，Agent 的来源决策与预期完全一致。

换成业务语言就是：

- 该走知识库的问题，都走到了知识库
- 没有出现明显“本该本地回答却跑去别处”的错误
- 说明当前这批样本下，Agent 的决策逻辑是稳定的

## 4. 纯 RAG vs Agent，应该怎么对比

建议从两个层面看：

### 4.1 第一层：回答质量有没有提升

看这 4 个 Ragas 指标：

- `faithfulness`：回答有没有乱编
- `answer_relevancy`：回答有没有答偏
- `context_precision`：喂给模型的材料准不准
- `context_recall`：关键材料找得全不全

如果 Agent 版本这四项整体更高，就说明它不只是“多了一套路由”，而是确实提升了最终问答质量。

本次结果属于这一类，而且是四项全面领先。

### 4.2 第二层：决策路径是不是正确

纯 RAG 没有“路由正确率”这个概念，因为它只有一条路径。

Agent 比纯 RAG 多出来的价值，就在于：

- 它会做来源判断
- 它会决定走知识库还是别的路径
- 它的错误不只是“答不好”，还可能是“路走错”

所以 Agent 评估必须额外看：

- `source_type`
- `route`
- `route_accuracy`

这部分是纯 RAG 评估没有覆盖到、但 Agent 必须补上的。

## 5. 本次结论

本次 50 条样本结果说明：

- Agent 版整体优于纯 RAG 基线
- 提升最明显的是 `faithfulness` 和 `context_precision`
- 说明 Agent 不只是“能路由”，而且让最终回答更可信、上下文更干净
- `route_accuracy = 1.0` 表明在当前样本上，Agent 决策路径没有跑偏

可以把这次结果概括为：

`当前 Agent 版本相较纯 RAG，不仅保持了回答相关性，还显著提升了证据一致性和检索纯度，具备继续作为主方案演进的价值。`

## 7. 下一步建议

下一步建议优先做三件事：

1. 扩充包含“应走网络/外部信息”的样本，验证 Agent 在混合场景下的真实路由能力。
2. 抽取低分样本做误差分析，重点看 `faithfulness` 和 `context_precision` 低分原因。
3. 把 Agent 与纯 RAG 的差异样本单独列出来，分析“为什么 Agent 更好”。
